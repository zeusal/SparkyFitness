# Agent setup checklist

Paste this into a coding agent running on the machine that will run the flows. It installs nothing without asking.

---

Set up Maestro on this Windows machine so I can run the SparkyFitness mobile UI flows locally against my Android phone. Work one step at a time, and stop and ask me whenever something is unclear or the choice is mine.

## Context

- This workspace is my SparkyFitness clone. The Maestro kit is on branch `test/maestro-local-kit` of my fork (remote `origin`), in `SparkyFitnessMobile/.maestro/`. Its `README.md` is the source of truth for setup, running and troubleshooting. Read it first without switching branches: `git fetch origin test/maestro-local-kit`, then `git show origin/test/maestro-local-kit:SparkyFitnessMobile/.maestro/README.md`.
- Shell: PowerShell. Phone: a Xiaomi on HyperOS, connected over USB. I already build and run the app from this repo (`pnpm run android -- --device`).

## Rules

1. **Look before you change.** For every prerequisite, first find out what is already there and which version:
   - `$PSVersionTable.PSVersion`, `git --version`, `node -v`, `pnpm -v`
   - Java: `java -version`, `where.exe java`, `$env:JAVA_HOME`, `[Environment]::GetEnvironmentVariable('JAVA_HOME','User')`, `[Environment]::GetEnvironmentVariable('JAVA_HOME','Machine')`, and if `JAVA_HOME` is set, `& "$env:JAVA_HOME\bin\java.exe" -version` (Maestro uses that Java when `JAVA_HOME` is set).
   - adb: `adb version`, `where.exe adb`. If several adb copies are found, use the Android SDK one by full path (`& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"`) and tell me. `ANDROID_HOME` is informational only; a USB phone does not need it.
   - Maestro: `maestro --version`, `where.exe maestro` (ask the analytics question in rule 4 first).

   Then show me a short table: item, what you found (path and version), what the kit needs, and OK / missing / needs attention. Do not install anything before I have seen it.

2. **Ask before any change to my machine.** Never install, upgrade or uninstall software, and never change environment variables (`PATH`, `JAVA_HOME`, `MAESTRO_*`) without my explicit yes. When you ask, give the exact command, say what it changes, and say how to undo it. After the table, ask all the independent choices in one numbered message; ask separately only when one answer depends on another.
3. **Java.** The kit needs Java 17 or newer (17 or 21 recommended). If `JAVA_HOME` already points to a JDK 17 or newer, leave it alone: Gradle uses it for my Android builds. If Java is missing or older than 17, offer me these options: (0) no machine change, set `$env:JAVA_HOME` to Android Studio's `jbr` folder only in the shell that runs maestro; (1) use Android Studio's JBR permanently; (2) install Temurin 17.
4. **Maestro.** Before your first `maestro` command, ask whether to set `MAESTRO_CLI_NO_ANALYTICS=1`; if yes, run `$env:MAESTRO_CLI_NO_ANALYTICS = '1'` in your shell first. Use CLI 2.12.1 (the version the kit was written against) unless I say otherwise; if another version is installed, tell me and ask whether to keep it. To install, after my yes, use the PowerShell commands in README Setup step 3 (`$ProgressPreference = 'SilentlyContinue'` first, then download to `$env:LOCALAPPDATA\Programs\maestro-2.12.1`, keep the old user `Path` in `$old`, add `maestro\bin` with `[Environment]::SetEnvironmentVariable('Path', ..., 'User')`, and `$env:Path += ...` for your own shell). Never use `setx` for `PATH`. Tell me that other terminals see the change only after VS Code is fully restarted, and give me the undo.
5. **Getting the kit.** Do not touch my current branch or working tree: never stash, reset, clean or check out anything there. First run `git remote -v` (origin must be my fork), `git worktree list` and `git ls-remote origin test/maestro-local-kit`; if the last one prints nothing, stop and tell me the branch is not pushed. Then `git fetch origin test/maestro-local-kit`. After my yes, create a detached worktree with no local branch, next to the repo root: `$wt = Join-Path (Split-Path (git rev-parse --show-toplevel)) 'SparkyFitness-maestro'; git worktree add --detach $wt origin/test/maestro-local-kit`, and show me the absolute path. Update later with the same fetch and `git -C $wt checkout --detach origin/test/maestro-local-kit`; undo with `git worktree remove $wt`.
6. **The phone.** Run `adb devices`: the phone must show as `device`, not `unauthorized` or `offline`. Always pass its serial (`adb -s <serial>`, `maestro --device <serial>`), even when only one device is listed; if several are listed, ask me which one. You cannot reliably check the Xiaomi developer options, so ask me to confirm that USB debugging, Install via USB and USB debugging (Security settings) are on. List the SparkyFitness packages with `adb -s <serial> shell pm list packages | Select-String -Pattern sparky` (filter on the computer; the on-device filter is case-sensitive) and ask me which one to test. Never run `flows-clean-install/` against `com.SparkyApps.SparkyFitnessMobile` or `org.SparkyApps.SparkyFitnessMobile1.dev` (the guard refuses anything that does not end in `.e2e`).
7. **Phone settings.** Before changing anything on the phone (the app's language, the animation scales, `adb reverse`), read and show me the current value so it can be restored, ask me, and only then change it. At the end, give me the exact commands to put each one back (README Setup steps 6 to 8).
8. **My processes.** Do not start Metro, the server or an app build yourself. Ask me to start them in my own terminal and to tell you when they are ready. You may run `adb -s <serial> reverse tcp:8081 tcp:8081` after asking.
9. **Check that Maestro reaches the phone.** Before any flow, ask me to keep the phone unlocked with the screen on and to accept two install prompts on it (Maestro's helper apps `dev.mobile.maestro` and `dev.mobile.maestro.test`; HyperOS may show a countdown or a security scan first). Then run `maestro --no-ansi --device <serial> hierarchy --compact` (`--device` goes before `hierarchy`). A list of screen elements means it works. Each normal run installs and removes the helpers again, so the prompts come back every run; if you use `--no-reinstall-driver`, add `adb -s <serial> uninstall dev.mobile.maestro` and `adb -s <serial> uninstall dev.mobile.maestro.test` to the undo list.
10. **First run, safe flows only.** First check that the app under test is in English: `adb -s <serial> shell cmd locale get-app-locales <package>`; if not, do README Setup step 6 following rule 7. Then run only the default suite, from the worktree: `maestro --no-ansi test <worktree>\SparkyFitnessMobile\.maestro --device <serial> -e APP_ID=<package> --test-output-dir <worktree>\SparkyFitnessMobile\.maestro-results`. It takes several minutes: run it with a timeout of at least 15 minutes, or give me the command to run myself and ask me to paste the summary. Do not run `flows-data/` or `flows-clean-install/` unless I ask: the first writes data to the signed-in account, the second wipes the app.
11. **Secrets.** Never ask me to paste a password or API key into this chat, and never write one to a file or a persistent environment variable. Do not run flows that need `API_KEY` yourself: give me the full command to run in my own terminal (README "Secrets" and "Data flows"), with the key read through `Read-Host` (PowerShell 7: `-MaskInput`; Windows PowerShell 5.1: `-AsSecureString` with `NetworkCredential`) and passed as `-e "API_KEY=$env:SPARKY_E2E_API_KEY"`. Maestro stores every `-e` value in plain text in the run's `commands.json` and `maestro.log` (always pass `--test-output-dir` and `--debug-output` so both stay in `.maestro-results`, and never add `--verbose`): never open, print or paste those files from a run that had `API_KEY`, and remind me to delete that run's folders afterwards.
12. **Failures.** If a step fails, show me the relevant output, check the README's Troubleshooting section, propose a fix and ask before applying it. Do not retry the same thing in a loop.
13. **Repository.** Do not commit, push, open pull requests or edit files in the repo. If you think the kit needs a change, describe it and ask.

## When you finish

Give me a summary with: what was already installed; what you installed or changed, each with its undo command (PATH, JAVA_HOME, the worktree, phone settings, Maestro's helper apps if kept, Caddy or a CA certificate if one was used); the result of the first run (each flow passed or failed, and where the screenshots are); and anything left for me to do.
